# Architecture

A 5-minute tour of how the template fits together. For deep dives see [blocks.md](blocks.md) and [scripts.md](scripts.md).

## Project layout

```
src/
  blocks/                  ← page-builder blocks. one folder per block + an index that registers them
  cms/                     ← sanity schemas, groq queries, generated types
  components/              ← astro components (core, layout, misc)
  modules/                 ← (gone) old per-block JS pattern. all replaced by behaviors.
  pages/                   ← astro routes ([...slug].astro fans out to sanity content)
  scripts/
    core/                  ← the kernel — DO NOT EDIT. defineService / defineBehavior live here.
    services/              ← global singletons (locomotive, swup, grid-helper) — drop a file in here.
    behaviors/             ← global DOM-selector behaviors — drop a folder in here.
    utils/                 ← string/maths/etc helpers
  stores/                  ← nanostores (mouse, scroll, screen)
  styles/                  ← global CSS, theme tokens
sanity.cli.ts              ← Sanity CLI config (loads .env)
sanity.config.ts           ← Sanity Studio config (also loads .env in CLI contexts)
astro.config.mjs           ← Astro config (Tailwind, React, Sanity integration)
schema.json                ← extracted Sanity schema (regenerated by `bun run typegen`)
```

## The page builder

The render path for any URL:

```
[...slug].astro              fetches `page` from Sanity by slug
   │
   ▼
RenderBlocks (sections=…)    iterates the array of blocks
   │
   ▼
blocks registry              src/blocks/index.ts maps _type → astro component
   │
   ▼
<HeroBlock data={...} />     each block renders itself with its slice of CMS data
```

The single source of truth is `src/blocks/index.ts` — adding an entry there wires the block into both the Sanity schema (`sections.type.ts` reads from this list) and the renderer. See [blocks.md](blocks.md).

## The script kernel

Two primitives, period:

- **Service** — a singleton tied to a lifecycle. `scope: "app"` runs once on `app:ready`. `scope: "page"` runs on every `page:enter`, cleans up on `page:leave`. Examples: locomotive scroll, swup itself, grid-helper.
- **Behavior** — DOM-selector-driven, one instance per matching element. Mounted on `page:enter`, unmounted on `page:leave`. Examples: `data-text-reveal`, `data-hero-block`.

Lifecycle events are emitted by whatever owns page transitions (swup, in this template). The kernel doesn't know or care which transition library you use — `services/transitions.ts` could be replaced wholesale and the kernel wouldn't change.

See [scripts.md](scripts.md) for both recipes.

## Page transitions

[swup](https://swup.js.org) handles SPA-style page swaps. The `<main id="swup" data-swup-transition>` element in `base.astro` is the swap container. Swup loads the new HTML, replaces `<main>`, and updates `<head>` assets via `SwupHeadPlugin` (`awaitAssets: true`). New `<script>` tags from the incoming page execute before `page:enter` fires, so any `defineBehavior` calls in block astro files have already registered by the time the kernel mounts behaviors against the new DOM.

`is-ready`, `is-transitioning`, and `is-animating` classes on `<html>` drive the CSS fade — see `src/styles/page-transition.css`.

## Design principles

- **Per-route splitting is non-negotiable.** Block-scoped scripts live in the block folder, imported via the block's astro `<script>` tag — Astro hoists each as a separate Vite entry. A page that doesn't use a block doesn't ship that block's JS.
- **The kernel doesn't own project code.** `core/` knows about lifecycle, services, and behaviors. It doesn't know about swup, locomotive, GSAP, or any specific feature. Swap any of those out by editing only `services/`.
- **Declarative DOM hooks.** Behaviors target `data-*` attributes, not classes or IDs. Markup tells you what behaviors apply — no hidden coupling to selectors elsewhere.
- **Cleanup is the contract.** Every `mount()` returns a cleanup function. Every page service can return a cleanup. Page transitions tear everything down cleanly so the next page starts from a known-empty state.
- **One source of truth per concern.** Blocks register once in `src/blocks/index.ts`; that drives schema, types, and rendering. Env vars live in `.env`; both Astro and Sanity CLI read it.
- **Conventional naming.** Files are kebab-case. Components are PascalCase. Interfaces are `I`-prefixed. Data attributes match the behavior name (`data-text-reveal` ↔ `name: "text-reveal"`).

## Stack reference

| Layer | What |
|---|---|
| Framework | Astro 6 (static + ISR-friendly) |
| Content | Sanity v5 (studio mounted at `/admin`) |
| Styling | Tailwind v4 via Vite plugin |
| Smooth scroll | Locomotive Scroll v5 |
| Animation | GSAP (lazy-loaded per block / per behavior) |
| Page transitions | Swup v4 + head-plugin + preload-plugin |
| State | nanostores |
| Runtime | Bun ≥ 22.12 |
